## Usage

Link the stylesheet, and add the script once near the end of the page:

```html
<link rel="stylesheet" href="./styles/context-menu.css">
<script src="./javascripts/context-menu.js" defer></script>
```

The trigger points to its menu with `aria-controls`. The menu starts hidden, and each item is an element with a menu role and `tabindex="-1"`:

```html
<div class="np-context-menu-trigger" aria-controls="file-menu">Right click here</div>

<div class="np-context-menu-content" id="file-menu" role="menu" hidden>
  <div class="np-context-menu-item" role="menuitem" tabindex="-1">Profile</div>
  <div class="np-context-menu-item" role="menuitem" tabindex="-1">Billing</div>
  <div class="np-context-menu-item" role="menuitem" tabindex="-1">Team</div>
</div>
```

You can use the data attributes instead of classes: `data-np-context-menu-trigger`, `data-np-context-menu-content` and the other hooks in the reference below.

Every item is a plain element, so listen for `click` on it to run your action.

## Composition

Use the following composition to build a context menu:

```text
ContextMenu
├── ContextMenuTrigger
└── ContextMenuContent
    ├── ContextMenuLabel
    ├── ContextMenuItem
    ├── ContextMenuGroup
    │   └── ContextMenuItem
    ├── ContextMenuCheckboxItem
    ├── ContextMenuRadioGroup
    │   └── ContextMenuRadioItem
    ├── ContextMenuSub
    │   ├── ContextMenuSubTrigger
    │   └── ContextMenuSubContent
    ├── ContextMenuSeparator
    └── ContextMenuShortcut
```

| Name | Data attribute | Class alias |
| ---- | -------------- | ----------- |
| Destructive | `data-variant="destructive"` | `np-context-menu-destructive` |

### Roles and states

| Element | Role and state |
| ------- | -------------- |
| Menu and submenu content | `role="menu"` and the `hidden` attribute |
| Item | `role="menuitem"` and `tabindex="-1"` |
| Checkbox item | `role="menuitemcheckbox"` and `aria-checked` |
| Radio item | `role="menuitemradio"` and `aria-checked`, inside a `role="group"` |
| Disabled item | `aria-disabled="true"` or `data-disabled` |
| Submenu trigger | `aria-haspopup="menu"` and `aria-expanded` |


### Script

The script does what a menu needs and CSS cannot:

- Right click on the trigger opens the menu at the pointer. A long press opens it on touch screens.
- The menu stays inside the window, and flips to the other side of the pointer when it runs out of room.
- It closes on `Escape`, on a click outside, on scroll, on resize, and when an item is chosen. Checkbox and radio items keep it open.
- Hovering an item highlights it. Hovering a submenu trigger opens its submenu.
- Keyboard: `ArrowDown`, `ArrowUp`, `Home` and `End` move between items, `Enter` and `Space` choose, `ArrowRight` opens a submenu, and `ArrowLeft` or `Escape` closes it.
- Checkbox and radio items toggle `aria-checked`. A radio item unchecks the other radio items in its `role="group"`.

Without the script the menus stay hidden. They are not placed against the viewport edge with collision handling like the [React version](/docs/components/react/context-menu), and there is no type-ahead.
