## Usage

Link the component's CSS file to your HTML document. Add the stylesheets of the controls you use, such as [Input](/docs/components/html/input), [Textarea](/docs/components/html/textarea), [Checkbox](/docs/components/html/checkbox), and [Separator](/docs/components/html/separator).

```html
<head>
  <link rel="stylesheet" href="./styles/tokens.css">
  <link rel="stylesheet" href="./styles/label.css">
  <link rel="stylesheet" href="./styles/separator.css">
  <link rel="stylesheet" href="./styles/input.css">
  <link rel="stylesheet" href="./styles/field.css">
</head>
```

Then, build a field with the `np-field-*` classes.

```html showLineNumbers
<fieldset class="np-field-set">
  <legend class="np-field-legend">Profile</legend>
  <p class="np-field-description">This appears on invoices and emails.</p>

  <div class="np-field-group">
    <div class="np-field" role="group">
      <label class="np-field-label" for="name">Full name</label>
      <input id="name" class="np-input" autocomplete="off" placeholder="Evil Rabbit" />
      <p class="np-field-description">This appears on invoices and emails.</p>
    </div>

    <div class="np-field" role="group" data-invalid>
      <label class="np-field-label" for="username">Username</label>
      <input id="username" class="np-input" autocomplete="off" aria-invalid="true" />
      <div class="np-field-error" role="alert">Choose another username.</div>
    </div>

    <div class="np-field np-field-horizontal" role="group">
      <input id="newsletter" type="checkbox" class="np-checkbox" />
      <label class="np-field-label" for="newsletter">Subscribe to the newsletter</label>
    </div>
  </div>
</fieldset>
```

Every part also works with a `data-np-*` attribute instead of the class, for example `data-np-field` and `data-np-field-label`.

## Composition

### Field

A single control with label, helper text, and validation.

```text
Field
├── FieldLabel
├── Input / Textarea / Checkbox
├── FieldDescription
└── FieldError
```

### FieldGroup

Related fields in one group. Use `FieldSeparator` between sections when needed.

```text
FieldGroup
├── Field
│   ├── FieldLabel
│   ├── Input / Textarea / Checkbox
│   ├── FieldDescription
│   └── FieldError
├── FieldSeparator
└── Field
    ├── FieldLabel
    └── Input / Textarea / Checkbox
```

### FieldSet

Semantic grouping with a legend and description, usually containing a `FieldGroup`.

```text
FieldSet
├── FieldLegend
├── FieldDescription
└── FieldGroup
    ├── Field
    │   ├── FieldLabel
    │   ├── Input / Textarea / Checkbox
    │   ├── FieldDescription
    │   └── FieldError
    └── Field
        ├── FieldLabel
        └── Input / Textarea / Checkbox
```

## Orientation

Use `data-orientation` or the matching class on `np-field`.

| Orientation | Data attribute                  | Class alias           |
| ----------- | ------------------------------- | --------------------- |
| Vertical    | `data-orientation="vertical"`   | `np-field`            |
| Horizontal  | `data-orientation="horizontal"` | `np-field-horizontal` |
| Responsive  | `data-orientation="responsive"` | `np-field-responsive` |

---

## Legend variant

The legend has two sizes. The `label` variant uses label sizing, which is handy for nested fieldsets.

| Variant | Data attribute         | Class alias             |
| ------- | ---------------------- | ----------------------- |
| Legend  | `data-variant="legend"` | `np-field-legend`       |
| Label   | `data-variant="label"`  | `np-field-legend-label` |

```html
<legend class="np-field-legend np-field-legend-label">Notification Preferences</legend>
```

## Responsive Layout

- **Vertical fields:** the default orientation stacks label, control, and helper text.
- **Horizontal fields:** use `np-field-horizontal` to align the label and control side-by-side. Pair with `np-field-content` to keep descriptions aligned.
- **Responsive fields:** use `np-field-responsive` for automatic column layouts. `np-field-group` is a container, and responsive fields switch to a row when it is at least `28rem` wide. A responsive field outside a field group stays vertical.

## Validation and Errors

- Add `data-invalid` to `np-field` to switch the entire block into an error state.
- Add `aria-invalid="true"` on the control itself for assistive technologies.
- Put `np-field-error` right after the control, with `role="alert"`. Connect it with `aria-describedby`.

Link the following stylesheets:

```html
<link rel="stylesheet" href="./styles/label.css">
<link rel="stylesheet" href="./styles/input.css">
```

<ComponentPreview
  name="field-error"
  target="html"
  styles={["/label/label.css", "/input/input.css"]}
/>

```html /data-invalid/ /aria-invalid="true"/
<div class="np-field" role="group" data-invalid>
  <label class="np-field-label" for="email">Email</label>
  <input id="email" class="np-input" type="email" aria-invalid="true" aria-describedby="email-error" />
  <div id="email-error" class="np-field-error" role="alert">Enter a valid email address.</div>
</div>
```

For several messages, put a list with the `np-field-error-list` class inside `np-field-error`.

## Accessibility

- `np-field-set` and `np-field-legend` on a native `<fieldset>` and `<legend>` keep related controls grouped for keyboard and assistive tech users.
- Give each `np-field` `role="group"` so nested controls inherit labeling from the label and legend.
- Always connect labels and controls with `for` and `id`.
- Use `np-field-separator` sparingly to ensure screen readers encounter clear section boundaries.
