## Usage

```tsx
import {
  PasswordInput,
  PasswordInputControl,
  PasswordInputToggle,
} from "@/components/nepui/password-input"
```

Wrap it in a [Field](/docs/components/react/field) so it gets a label and a description. Give the root an `id` and point the label at it.

```tsx
<Field>
  <FieldLabel htmlFor="password">Password</FieldLabel>
  <PasswordInput id="password">
    <PasswordInputControl />
    <PasswordInputToggle />
  </PasswordInput>
  <FieldDescription>Use at least 8 characters.</FieldDescription>
</Field>
```

Without a `Field`, name the control with `aria-label`:

```tsx
<PasswordInput name="password">
  <PasswordInputControl aria-label="Password" />
  <PasswordInputToggle />
</PasswordInput>
```

## Composition

```text
PasswordInput
├── PasswordInputAddon        (optional, before the control)
├── PasswordInputControl
├── PasswordInputCapsLock     (optional)
├── PasswordInputAction       (optional, any number)
└── PasswordInputToggle

PasswordInputStrength         (optional, after the field)
PasswordInputRequirements     (optional, after the field)
└── PasswordInputRequirement
```

`PasswordInput` holds the value and the visibility state and draws the field box. `PasswordInputControl` renders the native input. `PasswordInputToggle` is a `type="button"`, so pressing Enter in the control still submits the form.

Put form options such as `name`, `form`, `required`, `disabled`, `readOnly` and `autoComplete` on `PasswordInput`. Put other native input attributes, such as `placeholder`, on `PasswordInputControl`.

The strength meter and the checklist go **outside** the box, as siblings after `PasswordInput`.

## Controlled visibility

Pass `visible` and update it in `onVisibleChange`. `details.reason` says why it changed: `toggle-press`, `form-submit`, `reset`, `page-hide` or `imperative`. Call `details.cancel()` to reject the change.

<ComponentPreview
  name="password-input-controlled"
/>

During form submission the native input is a password field for a moment even if you reject hiding it, so the browser can read the form.

## Controlled value

Pass `value` and update it in `onValueChange`.

```tsx
const [password, setPassword] = React.useState("")

<PasswordInput value={password} onValueChange={(value) => setPassword(value)}>
  <PasswordInputControl aria-label="Password" />
  <PasswordInputToggle />
</PasswordInput>
```

## Render functions and state

`className` and `children` can be functions of the state. Every part gets the same state.

```tsx
<PasswordInput>
  {(state) => (
    <>
      <PasswordInputControl />
      <PasswordInputToggle>
        {state.visible ? <EyeOffIcon /> : <EyeIcon />}
      </PasswordInputToggle>
    </>
  )}
</PasswordInput>
```

The toggle already shows an eye icon by default. Pass your own children to replace it.

### createPasswordInputController

Returns a controller. Every write method takes an optional `{ reason, event }` and returns `false` when the change is canceled or does nothing.

| Method | Description |
| ------ | ----------- |
| `getValue()` | The current value. |
| `setValue(value, options?)` | Sets the value. |
| `clear(options?)` | Empties the control. |
| `isVisible()` | Whether the password is shown. |
| `setVisible(visible, options?)` | Shows or hides the password. |
| `toggleVisible(options?)` | Flips visibility. |
| `focus()` | Moves focus to the control. |

## Accessibility

There is no WAI-ARIA pattern for a password field. The control stays a native password field named by its label or `aria-label`. The toggle follows the [button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) as a toggle button, with `aria-pressed` and `aria-controls`.

- Tab moves from the control to the toggle. Space or Enter on the toggle shows or hides the password.
- Enter in the control submits the form. It never presses the toggle.
- A pointer press on the toggle keeps the caret and selection in the control. A press from elsewhere brings focus back to the control. A keyboard press keeps focus on the toggle.
- A shown password is never spellchecked, autocorrected or capitalized.
- The browser's own reveal button in Edge is hidden so there is only one.
- The strength meter has `role="meter"` with `aria-valuenow` and `aria-valuetext`.
- The Caps Lock chip has `role="status"`.
