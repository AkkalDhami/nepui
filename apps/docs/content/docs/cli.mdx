Use the nepui CLI to initialize a project and add component source files directly into your app.

```bash
npx nepui@latest init --target react
```
```bash
npx nepui@latest init --target html
```
```bash
npx nepui@latest init --target react --src .
```
```bash
npx nepui@latest add button card spinner
```
```bash
npx nepui@latest add --all
```

No separate install step is required. Run the CLI on demand with `npx`, or pin a version in CI with `npx nepui@latest`.

## Initialize a project

```bash
npx nepui@latest init [directory] [--target <html|react>] [--src <path>]
```

`init` creates `nepui.json` in the selected project directory and writes the
base token stylesheet under the configured source root. If `--target` or
`--src` is omitted, the CLI prompts for it. The source root defaults to `.`.

Examples:

```bash
npx nepui@latest init --target react
```
```bash
npx nepui@latest init --target html
```
```bash 
npx nepui@latest init --target react --src .
```

```bash
npx nepui@latest init --target react .
```
```bash
npx nepui@latest init --target react my-app
```
```bash
npx nepui@latest init --target html my-app
```

```bash
npx nepui@latest init
```

Without options, the CLI prompts for a target and source root and uses the
current directory. A positional directory selects a different project root.

The generated configuration looks like this:

```json
{
  "$schema": "https://nepui.vercel.app/schema.json",
  "target": "react",
  "src": "./src"
}
```

For React projects, it writes the base token file to `components/nepui/tokens.css`.
For HTML projects, it writes it to `styles/tokens.css`.
Both paths are relative to the configured `src` directory. For example, with
`"src": "./src"`, React tokens are written to `src/components/nepui/tokens.css`.

React initialization also installs the required dependencies for the project when needed.

## Install components

```bash
npx nepui@latest add <component> [<component>...] [--target <html|react>]
```

You can add:

- one component
- multiple components
- every available component with `--all`

Examples:

```bash
npx nepui@latest add button card spinner
```
```bash
npx nepui@latest add button card spinner --target html
```
```bash
npx nepui@latest add --all
```

`add` reads the `target` and `src` values from `nepui.json`. An explicit
`--target` overrides the configured target. If `nepui.json` is missing, the
CLI asks whether to create it. Choosing yes runs the initialization prompts
for target and source root, creates the config and token stylesheet, then adds
the requested components. Choosing no cancels the add.

The CLI installs package `dependencies` and `devDependencies` declared by
fetched component registry items using the project's detected package manager.

If a destination file already exists, the CLI asks whether to overwrite it, skip it, or cancel. Nothing is silently replaced. An unknown component name or an invalid `--target` value fails immediately, and no files are written.

Use either component names or `--all`; do not combine them in the same command.

## List available components

```bash
npx nepui list [--target <html|react>] [--json]
```

Aliases:

```bash
npx nepui ls
```
```bash
npx nepui ls --target react
```
```bash
npx nepui ls --json
```
```bash
npx nepui ls --json --target react
```

By default, the CLI lists components for the `html` target. Plain output is an alphabetical list. With `--json`, it prints only the JSON object to stdout, which is safe to pipe into tools like `jq`.

## Reference

| Option | Description |
| --- | --- |
| `-V, --version` | Print the installed CLI version |
| `-h, --help` | Show help for `nepui` or any subcommand |
| `init --target` | Select the project target |
| `init --src` | Set the source root, relative to the project directory |
| `add --target` | Override the target from `nepui.json` |
| `list --target` | Select the target for listing components |
| `list --json` | Print the JSON object to stdout |
